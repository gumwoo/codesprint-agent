# ADR-0052 · Explain Back 은 무엇을 심었는지 적은 설명으로 잰다

- 상태: 채택
- 날짜: 2026-09-27
- 정본 근거: PRD §148(Explain Back), [ADR-0016](0016-reviewer-accuracy-is-measured-with-labelled-wrong-answers.md),
  [ADR-0029](0029-confirmation-respects-the-problems-declared-mistakes.md),
  [ADR-0050](0050-explain-back-is-analysed-and-not-recorded.md)

## 맥락

ADR-0050 은 Explain Back 의 경계(푼 문제만 · 기록하지 않음 · 점수 자리 없음)를 테스트로 지켰지만 "실제 모델로 분석
품질을 잰 적은 없다" 고 남겼다. Reviewer 는 ADR-0016 의 하네스로 실제 모델을 재 왔다(ADR-0029: 25건 · 오확정 0).

Reviewer 의 정답지는 CI 가 실제로 채점해 본 오답이다. 설명에는 채점이 없다 - "이 설명이 맞는가" 는 판정이 아니라
판단이다. 무엇을 정답지로 삼을지 정해야 했다.

## 결정

### 1. 무엇을 심었는지 적어 둔 설명을 정답지로 쓴다

`tests/eval/explain/<문제>__<라벨>.json` 에 설명과 **심은 것**을 적는다. 라벨은 넷이다.

| 라벨 | 설명에 무엇이 있는가 | 적어 두는 것 |
| --- | --- | --- |
| SOUND | 틀린 말이 없고, 이 문제에서 그 기법이 통하는 핵심 이유를 말한다 | - |
| MISSING | 틀린 말은 없지만 개념 자료의 요점 하나를 일부러 뺐다 | `omittedPoint` (요점 번호) |
| MISCONCEPTION | 틀린 주장 하나를 심었다 | `plantedMisconception` |
| VAGUE | 맞지도 틀리지도 않은, 구체성 없는 설명 | - |

null 을 허용하는 두 필드도 생략하지 않고 적는다. 여섯 문제(P01 · P02 · P05 · P73 · P55 · P46, PRIMARY 가 모두 다른
Skill)에 라벨마다 하나씩, 24건이다.

### 2. 실패는 오지적 하나, 성립하지 않음 하나

기준선을 두지 않는다(ADR-0016 과 같은 이유). `gradle evalExplain` 은 두 경우에만 실패한다.

```
오지적 0건         SOUND · MISSING 설명에 "잘못 이해한 점" 을 붙이면 안 된다     exit 1
평가가 성립했는가   쓸 수 있는 분석이 0건이면 아무것도 재지 않은 것이다            exit 2
```

맞게 이해한 사람에게 틀렸다고 말하는 것이 이 기능이 낼 수 있는 가장 나쁜 답이다. 기록은 남지 않아도 사람은 그 말을
믿는다. Reviewer 의 "오확정 0건" 자리다.

빠진 요점을 짚었는지, 심은 오개념을 찾았는지는 **보고만 한다.** 모델은 개념 자료와 다른 문장으로 말하므로 기계가
"같은 뜻" 이라고 셀 수 없다. 하네스는 심은 것과 모델의 답을 나란히 찍고, 같은 뜻인지는 사람이 읽는다.

### 3. 앱과 같은 입력 · 같은 설정

- 요청은 `ExplainService.request(...)` 가 조립한다. 앱과 하네스가 이 한 곳을 부른다. 따로 조립하면 잰 입력이 실제
  입력과 달라진다
- 명령 · timeout · 프롬프트 버전은 `application.yml` 의 `codesprint.explain` 에서 읽는다(`ReviewerSettings.load("explain", …)`).
  환경변수 이름도 앱과 같다

### 4. CI 는 정답지와 판정만 본다

모델 호출은 CI 에 넣지 않는다(ADR-0016). `ExplainEvalCasesTest` 가 모델 없이 두 가지를 본다.

- 정답지 규칙: 필드가 모두 있는가, 라벨과 파일 이름이 맞는가, 문제가 있는가, 그 PRIMARY Skill 에 개념 자료가 있는가,
  MISSING 의 요점 번호가 있는가, 라벨에 맞지 않는 심은 것이 없는가, 라벨마다 한 건 이상 있는가.
  규칙마다 그 규칙 하나만 어긴 케이스를 만들고, **그 규칙의 메시지로** 걸리는지 본다(파일 이름은 망가뜨린 뒤의 문제 ·
  라벨로 다시 짓는다 - 그대로 두면 다른 규칙이 대신 걸린다). 개념 자료 조회는 갈아 끼울 수 있게 두어, 자료가 없는
  Skill 도 시험한다
- 판정: SOUND · MISSING 오지적 → 1, MISCONCEPTION · VAGUE 지적 → 0, 분석 0건 → 2. **"붙였다" 는 화면과 같은 기준이다** -
  화면은 `if (analysis.misconception)` 이라 빈 문자열만 그리지 않으므로, 빈 문자열은 0 · 공백 한 칸은 1 이다

## 측정 (explain-v1, 2026-09-27, 같은 24건을 두 번)

두 번의 집계가 같았다. 두 번째는 뒤쪽 7건(P55 · P73 묶음)에서 Claude CLI 호출 자체가 실패해(모델 출력이 아니라 호출
실패다, 원인은 확인하지 못했다) 그 두 묶음 8건을 다시 돌려 합쳤다.

| 라벨 | 분석 | 잘못 이해한 점 있음 | 빠진 점 있음 |
| --- | --- | --- | --- |
| SOUND | 6 | 0 | 3 |
| MISSING | 6 | 0 | 6 |
| MISCONCEPTION | 6 | 6 | 6 |
| VAGUE | 6 | 1 | 6 |

```
케이스 24건 · 쓸 수 있는 분석 24건 (오지 않았거나 버려짐 0)
[OK] 오지적 0건
```

심은 것과 모델의 답을 나란히 읽은 결과(사람이 읽은 판단이지 기계 판정이 아니다):

- MISCONCEPTION 6건 - 두 번 모두 심은 오개념과 같은 것을 짚었다. 예: 누적합 경계는 A_l 이 빠진다고 말하고 1부터 셀 때와
  0부터 셀 때의 맞는 식을 함께 적었다
- MISSING 6건 - 두 번 모두 뺀 요점을 "빠진 점" 첫 항목으로 냈다. 개념 자료 문장 그대로이거나 이 문제에 맞춰 풀어 쓴 문장이다
- SOUND 의 "빠진 점" 3건(P02 · P55 · P73) - 설명에 없는 더 깊은 이유(격자를 그래프로 보는 것, 로그 시간이 나오는
  이유, 칸만 막으면 버리는 경로)를 댔다. 틀린 지적은 아니다
- VAGUE 의 "잘못 이해한 점" 1건(P02, 두 번 모두 같은 건) - 설명의 "그렇게 하니 예제가 맞게 나왔다" 를 **예제 통과를
  통하는 이유로 든 것**으로 읽었다. 설명에 적힌 문장을 짚은 것이지 없는 이유를 지어낸 것은 아니다. VAGUE 에는 기대하는
  답이 없어 실패로 치지 않았다

처음 쓴 정답지에서는 VAGUE 두 건("격자 문제는 BFS 로 풀면 된다", "최단거리니까 BFS 다")이 겉모양 하나로 기법을 고르는
**일반화**를 담고 있어, "맞지도 틀리지도 않은" 정의에 맞지 않았다(검증 에이전트). 모델은 그 일반화를 짚었다. 두 건을
일반화 없는 문장으로 바꾸고, 요점 둘을 뺐던 P02 MISSING 을 요점 하나만 빼게 고친 뒤 위처럼 다시 쟀다

## 남는 위험

- **정답지를 쓴 것도 LLM 이다.** 24건의 설명과 라벨은 이 저장소를 만드는 에이전트(Claude)가 썼다. "심은 것" 은 만든
  방식으로 정해지지만(MISSING 은 요점을 빼고, MISCONCEPTION 은 틀린 주장 하나를 넣는다), SOUND 가 정말 틀린 말이 없는지는
  쓴 쪽의 판단이다. 같은 계열의 모델이 쓰고 같은 계열의 모델이 읽으므로, 사람이 쓴 설명보다 읽기 쉬울 수 있다.
  사람이 이 24건을 검토하고 사람이 쓴 설명을 더하는 것이 다음 할 일이다
- **24건 · 두 번이다.** 비결정적인 모델을 두 번 돌려 같은 집계가 나온 것은 흔들림이 작다는 약한 근거일 뿐이다.
  라벨당 6건으로는 비율을 말하지 않는다 - 그래서 위 표도 비율이 아니라 건수다
- 막연한 설명의 한 마디(예: "예제가 맞게 나왔다")도 모델은 주장으로 읽고 "잘못 이해한 점" 을 붙일 수 있다(1/6).
  실제 사용자에게 그대로 나간다. 프롬프트를 고치려면 새 파일(explain-v2)을 만들고 두 버전을 같은 24건으로 잰다 -
  이 집합을 보고 v1 을 고치지 않는다
- 모델은 문제 본문을 받지 않는다(제목 · Skill · 개념 자료 · 질문 · 설명만). 문제에 고유한 조건(예: P05 는 시작 칸도
  센다)을 말한 설명이 개념 자료와 달라 보일 수 있다. 이번 24건에서는 오지적으로 이어지지 않았다
- 평가는 CI 에 없다. 모델이나 프롬프트가 바뀌면 사람이 `gradle evalExplain` 을 다시 돌려야 한다
