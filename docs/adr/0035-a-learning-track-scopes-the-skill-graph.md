# ADR-0035 · 학습 트랙이 켜지는 Skill 범위를 정한다

- 상태: 채택
- 날짜: 2026-09-26
- 정본 근거: PRD §56(초기 진단 입력: 목표 난이도), §129(목표별 권장 범위), §152(사용자 설정),
  [ADR-0009](0009-mastery-is-recomputed-from-evidence.md),
  [ADR-0018](0018-the-diagnostic-orders-problems-it-does-not-score.md),
  [ADR-0022](0022-unlock-next-names-where-to-go.md),
  [ADR-0034](0034-the-road-to-the-full-prd.md)

## 맥락

슬라이스 1 은 Skill 8 개가 전부 한 사용자에게 켜져 있었다. PRD 는 46 개 도메인을 요구한다.
다 켜 두면 입문자에게 BFS 최단거리 진단이 나가고, Skill 지도에 수백 개의 "모른다" 가 뜬다.

PRD §129 가 답을 이미 적어 두었다.

> 사용자가 어떤 목표를 선택하더라도 전체 커리큘럼 데이터는 존재하고 목표에 따라 활성
> 범위만 달라진다.

## 결정

### 1. 트랙은 커리큘럼 데이터다

`curriculum/tracks.yaml` 이 네 트랙(§129 의 입문 · 일반 취업 · 상위 기업 · 알고리즘 심화)을
갖는다. 켜지는 Skill 은 **domain 과 tier 가 모두** 트랙 안에 있는 것이다.

도메인만으로는 부족하다. 같은 Tree 도메인 안에 CORE(tree_dfs)와 INTERMEDIATE(lca)가
섞여 있다(PRD §33).

### 2. 트랙은 스스로 닫혀 있어야 한다

트랙 안의 Skill 이 트랙 밖의 선수를 요구하면 그 Skill 은 영원히 LOCKED 이고, Decision
Engine 은 선수를 채우라며 사용자를 트랙 밖으로 보낸다. `check_curriculum.py` 가 막고,
메타테스트가 JOB 에서 FOUNDATIONS 를 빼 보면 실제로 걸리는지 본다. 빈 트랙과 없는 도메인도
같이 막는다.

### 3. 범위는 한 곳에서 거른다

`MasteryService.statesOf` 가 사용자의 트랙으로 거른 Skill 만 돌려준다. 진단(ADR-0018),
Skill 지도, 다음 행동이 전부 이 목록 위에서 돈다 - 소비하는 쪽마다 거르면 한 곳을 잊는다.

그래도 한 곳은 따로 막았다. `NextSkillSelector` 는 선수 그래프(전체)에서 "이번 숙달이 연
Skill" 을 찾는데, 그 Skill 이 트랙 밖일 수 있다. 목록에 없는 Skill 을 "아직 숙달하지 않음"
으로 치던 코드라 입문 사용자를 BFS 로 보냈을 것이다. 단위 테스트가 대조군(전체 범위에서는
BFS_BASIC 으로 간다)과 함께 본다.

### 4. 목표에는 기본값이 없다

`POST /api/users` 는 `track` 이 없으면 400 이다. 기본값을 두면 목표를 고르지 않은 사용자와
일반 취업 트랙을 고른 사용자가 구별되지 않는다 - 이 저장소가 null 과 생략을 구분하는 것과
같은 이유다. 이미 있던 사용자는 마이그레이션에서 슬라이스 1 범위를 담는 JOB 으로 두고
기본값을 걷었다.

### 5. 목표를 바꿔도 Evidence 는 남는다

`PUT /api/users/{id}/track` 은 범위만 바꾼다. mastery 는 Evidence 로부터 다시 계산되므로
(ADR-0009) 트랙을 바꿨다가 돌아와도 같은 값이 나온다.

### 6. 문제 번호는 세 자리로 넘어간다

도메인 46 개를 채우면 문제는 99 개를 넘는다. `P[0-9]{2,3}` 으로 넓히고, 100 미만은 두 자리
그대로 쓴다 - `P005` 처럼 앞에 0 을 붙이면 같은 번호가 두 code 를 갖는다(`check_problems`).
글자 순으로는 `P100` 이 `P11` 앞에 오므로 문제 순서는 번호로 정렬한다(`ProblemCatalog.BY_NUMBER`).

## 결과

- 화면 위쪽에 "목표" 선택이 생겼다. 목록과 Skill 수는 서버(`GET /api/tracks`)가 준다
- 사용자를 바꾸면 그 사람의 목표를 서버에서 읽는다. 늦게 온 이전 사용자의 목표가 지금
  사용자의 목표를 덮지 않는지 e2e 가 게이트로 본다 - 표 확인을 빼면 실제로 깨진다(대조군)
- 지금 켜진 Skill 은 8 개라 트랙별 차이는 INTRO(4) 와 나머지(8)뿐이다. 도메인 웨이브가
  들어올 때마다 트랙이 넓어진다

## 남는 위험

- 트랙을 바꾸면 이미 예약된 복습(ADR-0021)이 새 트랙 밖의 Skill 을 가리킬 수 있다. 복습은
  범위와 상관없이 이미 배운 것의 유지라 그대로 둔다
- 문제 목록(`GET /api/problems`)은 트랙으로 거르지 않는다. 학습 경로가 아니라 진입점이고,
  범위 밖 문제를 풀어도 Evidence 는 정상으로 쌓인다
