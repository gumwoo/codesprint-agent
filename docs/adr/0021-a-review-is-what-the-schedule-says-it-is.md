# ADR-0021 · 복습인지는 문제 종류가 아니라 일정이 정한다

- 상태: 채택
- 날짜: 2026-09-08
- 정본 근거: PRD §79, Addendum §16 · §22,
  [ADR-0001](0001-llm-analyzes-system-decides.md),
  [ADR-0009](0009-mastery-is-recomputed-from-evidence.md),
  [ADR-0019](0019-the-diagnostic-is-an-input-to-the-decision-engine.md)

## 맥락

`MASTERED` 의 네 조건 중 `reviewSucceeded` 만 도달할 수 없었다. PR #26 으로 산식은
Java 로 옮겼지만, **그 Evidence 를 만드는 런타임 경로가 없다.** 그래서 아직 아무도
`MASTERED` 가 되지 못하고, 그것을 요구하는 `UNLOCK_NEXT` 도 나오지 않는다.

만들 때 가장 쉽게 틀리는 지점이 하나 있다. `problems/` 에는 이미
`P10_BFS_REVIEW` 라는 `kind: REVIEW` 문제가 있다. 그것을 풀면 복습으로 치고 싶어진다.

**그러면 사용자가 자기 `MASTERED` 를 만들 수 있다.** 목록에서 P10 을 찾아 연달아 두 번
풀면 "간격을 두고도 됐다" 가 성립해 버린다. 간격 복습이 재는 것은 **시간이 지난 뒤에도
되는가**이지 어떤 문제를 풀었는가가 아니다.

이것은 힌트 자기신고를 걷어낸 것(PR #19)과 같은 부류다 — 측정 대상이 스스로 측정값을
정하게 두지 않는다.

## 결정

**복습 Evidence 는 그 제출이 만기된 일정과 이어질 때만 만든다.**

```
LLM · 클라이언트가 정하는 것    없음
시스템이 정하는 것              이 제출이 예약된 복습인가
                               직전 관측으로부터 며칠이 지났는가
```

`review_schedules` 행 하나가 그 연결이다. 없으면 그냥 제출이다.

### 문제 종류를 보지 않는다

`kind: REVIEW` 는 **큐레이션 표시**로 남는다 — 그 Skill 을 넓게 다시 훑는 문제라는 뜻.
복습으로 세느냐는 일정이 정한다. 그래서:

- 일정이 없는데 `P10` 을 풀면 → 평범한 제출이다
- 일정이 만기인데 `P02`(NORMAL)를 풀면 → 복습이다

뒤엣것을 허용하는 이유는 **REVIEW 문제가 있는 Skill 이 지금 하나뿐**이기 때문이다.
종류를 요구하면 나머지 일곱 Skill 은 영원히 `MASTERED` 가 될 수 없다 — 갈 곳 없는
액션을 또 만드는 셈이다.

### `daysSinceLast` 는 일정이 계산한다

직전 관측 시각을 일정 행이 들고 있고, 만기 제출이 들어올 때 그 차이를 서버가 잰다.
클라이언트는 이 값을 보내지 않는다.

**최소 1일을 일정이 보장한다.** 산식은 음수만 막는다(PR #26) — 0 을 산식에서 막으면
"며칠 간격이어야 복습인가" 를 산식이 정하게 되고, 그건 일정의 결정이다.

### 만기 복습은 Decision Engine 의 입력이다

진단과 같은 자리다(ADR-0019). 결정 주체는 하나로 두고, 만기 여부를 입력으로 넣는다.

```
SYSTEM_ERROR / COMPILE_ERROR   아무 데도 보내지 않는다
확정된 Mistake / 3회 실패        이 Skill 안에서 즉시 교정할 근거
진단 진행 중                     아직 아무것도 모른다
만기된 복습                      시간이 지났고, 지금 확인해야 한다
막힌 선수
그 밖
```

진단보다 뒤에 둔다. 진단은 "아무것도 모르는 상태" 를 메우는 일이고, 복습이 잡혀
있다는 것은 이미 그 Skill 을 충분히 했다는 뜻이라 급하지 않다.

### 간격은 성공하면 늘고 실패하면 줄어든다

PRD §79 를 그대로 옮긴다: `1 → 3 → 7 → 14 → 30`. 실패하면 한 칸 내린다.
**0 으로 내려가지 않는다** — 최소 1일이다.

## 결과

- `MASTERED` 에 실제로 도달할 수 있다. 그 경로를 테스트가 끝까지 밟는다
- `SCHEDULE_REVIEW` 가 갈 곳 없는 액션이 아니게 된다. 일정을 저장하고, 만기에
  문제를 준다
- 복습 성공/실패가 `retention` 차원의 유일한 관측이다. 그전까지 그 차원은 아무도
  채우지 않았다

### 남는 위험

- **시계에 의존한다.** 테스트는 `Clock` 을 주입해 시간을 옮긴다. 프로덕션 경로에는
  시간을 앞당기는 수단을 두지 않는다 — 두면 그것으로 `MASTERED` 를 만들 수 있다
- 일정은 (사용자, Skill) 당 하나다. 이력을 남기지 않으므로 "복습을 몇 번 했는가" 는
  Evidence 쪽에서 세어야 한다
- `UNLOCK_NEXT` 는 여전히 갈 곳이 없다. `MASTERED` 다음이 비어 있다 — 이 ADR 이
  닫는 것은 그 앞까지다
