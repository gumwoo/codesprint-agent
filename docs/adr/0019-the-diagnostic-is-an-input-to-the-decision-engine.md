# ADR-0019 · 진단은 Decision Engine 의 입력이지 두 번째 결정자가 아니다

- 상태: 채택
- 날짜: 2026-09-08
- 정본 근거: PRD "진단 → 학습 → 문제 → 실행 → 판정", PRD §75 · §88,
  [ADR-0002](0002-next-action-decided-by-rule-engine.md),
  [ADR-0018](0018-the-diagnostic-orders-problems-it-does-not-score.md)

## 맥락

[ADR-0018](0018-the-diagnostic-orders-problems-it-does-not-score.md) 로 진단을 붙이고
나니 **다음에 풀 문제를 가리키는 곳이 둘이 됐다.** 실측한 값이다 — P05 를 실패한
사용자에게:

```
진단           BFS_BASIC            P14_GRAPH_REACHABLE
Decision Engine  CHANGE_SKILL · BFS_GRID_TRAVERSAL   P02_GRID_TRAVERSAL
```

둘 다 자기 자리에서는 옳다. 진단은 **모르는 칸을 채우려** 하고(`BFS_BASIC` 은 Evidence 가
없다), Decision Engine 은 **막힌 선수를 채우려** 한다(`BFS_GRID_TRAVERSAL` 은 mastery 가
낮다). 목적이 다르니 답이 다르다.

문제는 사용자에게 그 사정이 보이지 않는다는 것이다. 화면 두 곳이 서로 다른 문제를
가리키고, 어느 쪽을 눌러도 학습은 진행되지만 **왜 다른지 설명할 방법이 없다.**

그리고 이것은 ADR-0002 와 정면으로 부딪친다. 다음 학습 행동의 결정 주체는 하나라고
못박아 두었는데, 실제로는 둘이 됐다.

## 결정

**진단을 Decision Engine 의 입력으로 넣는다.** 경쟁자가 아니라, mastery 나 확정된
Mistake 와 같은 자격의 입력이다. 결정 주체는 계속 하나다(ADR-0002).

```java
Context(..., masteries, diagnosticSkill)
```

규칙은 하나다. **진단이 끝나지 않았으면, 선수 조건 규칙 대신 진단이 답한다.**

### 대체하는 것은 선수 조건 규칙 하나뿐이다

그 둘이 **같은 질문에 답하기 때문이다** — "어느 Skill 로 갈 것인가". 진단은 안 재 본
칸을 채우려 하고, 선수 조건 규칙은 막힌 선수를 채우려 한다. 위에 적은 실측이 정확히
그 충돌이다.

처음에는 모든 규칙보다 앞에 두었다. **틀렸고, 테스트 10개가 그것을 잡았다.** 신규
사용자는 전부 진단 중이라 확정된 실수의 드릴도, 같은 문제 3회 실패의 개념 복습도,
문법 오류의 "고쳐서 다시 내라" 도 전부 덮였다. 그것들은 다른 질문에 답하고 있었다 —
"이 Skill 안에서 무엇을 할 것인가".

확정된 Mistake 가 진단보다 우선한다는 것은 뒤집어 보면 자연스럽다. 이미 관측된
구체적인 결함은 **그 자체가 "어디서부터" 의 답**이다. 아직 재 보지 않은 Skill 을
채우는 것보다 먼저 다룰 값이 있다.

근거는 PRD 의 흐름이다 — `진단 → 학습 → 문제 → 실행 → 판정`. 진단은 학습에 **앞서는
단계**다. 다만 앞선다는 것이 "그 동안 학습 규칙을 전부 멈춘다" 는 뜻은 아니었다.

### 새 ActionType 을 만들었다

`DIAGNOSTIC_PROBE` 는 **PRD §75 의 목록에 없는 값이다.** 그런데도 만든 이유는,
`CHANGE_SKILL` 로 적으면 "선수 조건을 채우러 간다" 와 "아직 재 보지 않았다" 가 한
값에 섞이기 때문이다. **이유가 다르면 값도 다르다** — Skill 과 Mistake 를 섞지 않는
것과 같은 규칙이다.

섞으면 나중에 "이 사용자가 진단 중이었는가" 를 제출 이력에서 되읽을 수 없다.

## 결과

- 화면 두 곳이 같은 문제를 가리킨다. 진단 카드와 결과 패널의 "다음" 이 일치한다
- 진단이 끝나면 그 다음 제출부터 평소 규칙이 그대로 돈다. 넘겨주는 이벤트가 따로
  없다 — 입력이 null 이 되면 규칙이 한 줄 건너뛴다
- 진단을 건너뛴 사용자와 마친 사용자가 여전히 같은 상태 기계를 탄다(ADR-0018)

### 대가

- **결과를 반영할 때마다 진단을 계산한다.** 진단은 전체 Skill 을 Evidence 에서 다시
  계산하므로(ADR-0009), 활성 Skill 수만큼 조회가 는다. 지금은 8개라 문제가 아니지만,
  Skill 이 수십 개가 되면 이 경로부터 아플 것이다
- **`CHANGE_SKILL` 에 닿기 어려워졌다.** 진단이 끝나고, 아직 Evidence 가 없는 Skill 을
  풀고, 그 선수가 막혀 있을 때만 나온다. 도달할 수 없어진 것은 아니지만 서비스
  테스트에서 저절로 밟히지는 않게 되어, **그 경로를 밟는 테스트를 따로 넣었다** —
  없으면 그 규칙이 죽어도 아무도 모른다

### 남는 위험

- 진단이 가리키는 Skill 에 NORMAL 문제가 없으면 갈 곳 없는 행동이 된다. 그래서
  **줄 문제가 있을 때만** 입력으로 넘긴다. 그 조건이 깨지면 사용자는 다음 문제를
  받지 못한다
