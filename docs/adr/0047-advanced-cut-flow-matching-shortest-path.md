# ADR-0047 · ADVANCED 단절점 · 단절선 · 유량 · 매칭 · 최단 경로 심화

- 상태: 채택
- 날짜: 2026-09-26
- 정본 근거: PRD §46(SCC / Articulation / Bridge), §47(Network Flow / Matching), §48(Advanced Shortest Path),
  [ADR-0033](0033-an-accepted-answer-does-not-prove-the-skill.md), [ADR-0034](0034-the-road-to-the-full-prd.md),

## 결정

### 1. Skill 다섯 - W9 의 둘째 갈래

| 도메인 | Skill | needs_skill_control | 문제 |
| --- | --- | --- | --- |
| SCC | ARTICULATION_POINT · BRIDGE | true · true | P122 · P127 |
| FLOW | MAX_FLOW · BIPARTITE_MATCHING | true · true | P128 · P124 · P125 |
| ADVANCED_SHORTEST_PATH | STATE_GRAPH_DIJKSTRA | true | P132 |

tier 는 ADVANCED 라 ALGORITHM 트랙에서만 켜진다. 단절점 · 단절선은 PRD 가 SCC 절(§46)에 둔 대로 SCC 도메인에
넣었다 - 그래서 이 갈래는 W9a 위에 있다.

### 2. 여러 출발점 최단 거리는 Skill 로 두지 않는다

처음에는 MULTI_SOURCE_SHORTEST_PATH 를 두고 P130(격자 여러 출발점 BFS)을 붙였다. 검증 에이전트 검토에서 둘 다
성립하지 않았다.

- **따로 관측할 수 없다.** 출발점마다 BFS 하되 더 좋아질 때만 넓히고 출발점 순서를 섞는 풀이는 기대 O(NM log S)
  라 어떤 case 로도 막히지 않았다(293ms). "출발점마다 따로 탐색하는 풀이는 끝나지 않는다" 는 정의가 사실이 아니다
- **이미 있다.** P130 은 기존 P15_MULTI_SOURCE_SPREAD(BFS_VISITED_MANAGEMENT)와 같은 계산이고, 가중치 있는 여러
  출발점 문제는 기존 P81_NEAREST_SHELTER_DISTANCE(DIJKSTRA)다. 새 문제는 둘 중 하나와 겹친다

ADR-0033 대로 채점으로 관측할 수 없는 Skill 은 합친다 - 여러 출발점은 BFS_VISITED_MANAGEMENT · DIJKSTRA 문제의
한 형태로 남는다. P130 은 철회했다(`generated/rejected` 에 stage "중복").

PRD 목록에서 Skill 로 두지 않은 것(Addendum §29 - Technique, 또는 같은 관측):

- `tarjan` · `kosaraju` · `ford_fulkerson` · `edmonds_karp` · `dinic` - 같은 결과를 내는 방법이다. 정의는 결과로
  적었다("그래프 크기에 비례하는 시간에", "다항 시간에")
- `zero_one_bfs` - 다익스트라가 같은 결과를 로그 배 안에 낸다. Python 에서 둘을 시간 제한으로 가를 수 없다
- `multi_source` - 위 2
- `k_shortest_basic` · `johnson_basic` - 코딩테스트 범위에서 드물고, 대조 풀이를 세우기 어렵다. 필요해지면 연다

## 남는 위험

- **단절선 · 단절점은 거의 선형인 다른 방법으로도 구한다.** 서로소 집합으로 트리 밖 간선의 경로를 합치는 풀이(308ms)와
  간선마다 무작위 값을 XOR 하는 해시 풀이(311ms)가 P127 에서, 뒷간선 덮기를 서로소 집합으로 건너뛰는 풀이(212ms)가
  P122 에서 AC 다. BRIDGE · ARTICULATION_POINT 의 Evidence 는 "효율적으로 구했다" 까지만 말한다
- P124 · P125 · P127 · P128 의 반례 case 는 사다리 · 가젯 · 미끼 간선 같은 인공 구조다. 답이 몇 가지뿐인 것은 아니지만 실제 입력과
  모양이 다르다. P125 의 가젯 case 는 확률적으로 막는다 - 무작위 되풀이를 아주 많이 하는 풀이가 뚫을 여지가 남는다
  (요소별 완전 탐색은 거대 요소 672 칸인 기존 case 11 이 막는다). P127 에서 양쪽 끝에서 번갈아 넓히는 탐색은 새 case 만으로는
  AC 지만 기존 case 11 이 막는다 - case 11 을 빼거나 바꾸면 안 된다. P128 도 쪼개고 합치기를 더 영리하게 하는 휴리스틱이
  남아 있을 수 있다
- MAX_FLOW 는 다항 시간 방법(에드몬드-카프 · 디닉 · 용량 스케일링)이 모두 들어온다 - 정의가 "다항 시간" 이다.
  P128 의 제약을 넓힌 것은 채택 뒤의 변경이다
- BIPARTITE_MATCHING 은 최대 유량으로도 풀린다. 둘 다 FLOW 도메인이고 같은 결과다
- STATE_GRAPH_DIJKSTRA 는 층을 K 번 쌓아 다익스트라를 K+1 번 도는 풀이도 들어온다 - 같은 상태 그래프를 다르게
  도는 것이다
- 시간 제한과 대조 풀이는 Python 기준이다(ADR-0045). C++ 로는 대조 풀이가 시간 안에 들어올 수 있다 - ADR-0046 의
  P115 · P118 과 같은 위험이며, 이 갈래에서 C++ 로 재 보지는 않았다
- 시도하지 않은 지름길이 남아 있을 수 있다. Skill 마다 문제가 하나다(매칭은 둘)
